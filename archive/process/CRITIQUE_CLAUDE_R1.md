# Claude-B Round 1 Critique

## Verdict

In its current state the submission cannot win on the v2 framing because **none of the three artifacts actually tell the two-tier story.** `VIDEO_SCRIPT.md`, `WRITEUP.md`, and `README.md` all still pitch the original single-tier "watch the red token stream past in a chat UI" demo. There is **zero mention** of `gemmaforge scan`, the leads JSONL, `pwnkit review --seed-findings`, the `--runtime ollama` agent loop, the 27B verifier, or the `/live` three-lane dashboard. The single dominant weakness is therefore not stylistic — it is that **the locked pitch and the shipped narrative are about different products.** A judge reading the writeup and watching the script would conclude this is a token-coloring overlay; they would never know the agent tier exists. Until Beat 4 of the video and the architecture section of the writeup are rebuilt around the scan → leads → pwnkit-verify climax, the project competes for the *old* score ceiling (~60 pts cap if the video is "fine") rather than the new one (genuine 90+).

## Risk flags

- **Disqualifying:** Video ends with `"Thanks for watching."` — explicitly forbidden by G2.7. Cheap fix but currently in the canonical script.
- **Likely embarrassing:** WRITEUP.md line 11 cites pwnkit as `PwnKit-Labs/pwnkit`. PR #371 is on `0sec-labs/pwnkit` (per ITERATION_GOALS §0 and `docs/events.md` line 3). Either the writeup link is to the wrong repo, or the project has been mirrored across two orgs and a judge clicking through will see inconsistent provenance. **Pick one canonical URL and use it everywhere** — `0sec-labs/pwnkit` is the one ITERATION_GOALS locks in.
- **Internal contradiction risk:** The locked v2 pitch claims the demo *is* the /live dashboard. The README still shows `web/screenshot-demo.png` (single-prompt streaming UI) as "what it looks like." If the video shows the dashboard but the repo's hero image shows the old UI, a judge sees two different products and trusts neither.
- **Coverage overclaim:** WRITEUP.md line 84 says "Mitigated with 8-token mean; proper fix needs per-token labels (Efe's parallel track)." README line 70 says the same. The two-tier pitch sidesteps this — Tier 2 verifies the lead, the probe doesn't have to be exact. The current text leaves the *probe alone* carrying the verification burden, which contradicts the v2 story that Tier 1 is *triage* and Tier 2 is *verification*.
- **License hedge:** Both README ("Apache-2.0-equivalent license") and WRITEUP ("Apache-2.0-equivalent license") describe Gemma's license that way. Gemma is under the **Gemma Terms of Use**, not Apache-2.0; calling it "equivalent" is defensible but the project's own code (probe weights, src) is true Apache-2.0. Make sure the writeup distinguishes *our code = Apache-2.0* from *Gemma model = Gemma Terms (open weights, commercial use allowed)*. A pedantic judge will ding "Apache-2.0-equivalent."
- **Backed-by-PR check:** Goals lock the v2 pitch to what shipped in `0sec-labs/pwnkit#371` — `--seed-findings`, `--runtime ollama`, `/live` dashboard. Whatever we *say* the video shows must match what that PR actually exposes. None of the current artifacts reference the PR's actual surface area, so when the rebuilds happen the refiner should pull verb-by-verb from the PR description rather than inventing flag names. **Do not claim "three lanes labeled Probe/Lead/Hunt" unless that's literally the label text in the merged dashboard.**
- **HF Space live demo URL drift:** WRITEUP line 7 says `https://gemmaforge.doruk.ch`. README line 26 says the HF Space `peaktwilight/gemmaforge`. Pick one canonical live demo URL — currently a judge has two and no signal as to which works.
- **Video URL placeholder:** WRITEUP.md line 8 still says `https://youtube.com/watch?v=TODO`. Obvious but worth flagging — must be filled before submission, and a stale `TODO` in the writeup is the kind of thing a judge spots first.
